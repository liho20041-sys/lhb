背景

基层公共安全风险形态已从显性、集中转向隐性、个体化、碎片化、苗头化；存量摄像头全域覆盖，但普遍缺“理解”能力；高密度聚集与动态流动交织、遮挡复杂的公共空间（如农贸市场）是代表性场景。

目标

面向存量摄像头研制低成本智能视觉传感组件，形成“事前预警—事中干预—事后回溯”闭环；只分析行为，不识别身份，可标准化交付与复制。

这份文档回答六个问题：是什么、读什么、怎么建、用什么建、往哪走、怎么验收。 六个问题对应六个章节，每章之间有过渡——先讲清系统长什么样，再讲分析对象是什么，然后讲两条实施路径、五类数据规划、三步演进方向，最后落到验收口径和需要需求方拍板的事项。读完这一份，读者应能建立对项目的完整认知，并知道当前该做什么、后续往哪走、需要谁配合什么。

一、是什么：三层处理 + 一个基座系统由哪几层组成，每层做什么、产出什么、验收什么

这个智能体不是“一个模型”，而是一个有眼睛、有大脑的完整系统——摄像头是眼睛，时空记忆库是大脑。主链只有三步：感知（建线）→ 理解（读线）→ 决策（用线）；记忆库横贯底部，是支撑三步的基座——感知向下写入，理解向上读取，决策向下查询。

每一层做什么、产出什么、验收什么

感知 建线
做什么
在每一帧画面中找点（检测），把同一人的点连成连续的线（单镜跟踪 + 跨镜关联）；质量评估标记哪些点不可信。
回答什么
谁在哪？是不是同一个人？
产出
带 ID 的时空曲线，写入记忆基座。
验收
稳——ID 不丢，遮挡后能恢复，轨迹连续。
理解 读线
做什么
读线的形态、线的突变、线与线的关系。分三级递进：
三级判断
① 识形态规则引擎识别已知苗头：逗留、徘徊、聚集、倒地、占道、禁区、共现
② 辨偏离只学正常基线，把不在任何已知正常簇中的线捞出来
③ 释归因视觉语言模型把统计偏离翻译成人能理解的描述
产出
语义标签——已知苗头、偏离候选、偏离描述。需要历史时从记忆基座读取。
验收
准——已知不漏，未知能捞，捞出来能解释。
决策 用线
做什么
把语义转成动作——调度（算力花在哪）、告警分级（处置级还是关注级）、分发（推给谁）、回溯（查记忆基座，找历史证据）。
回答什么
该不该管？怎么管？
产出
三类输出：处置级告警（事实判断，召回优先）、关注级线索（风险判断，精确优先）、共现关系图（周期汇总，人工研判）。
验收
快——延迟可接受，线索密度在运维可承受范围内，回溯检索响应快。

二、读什么：时空中的六种线系统的分析对象是什么，不同线形态对应什么风险语义

系统的分析对象是每个人在时空中留下的一条线。不同的线形态对应不同的风险语义——正常穿行是平滑的线，异常逗留是水平段，反复徘徊是折返线，倒地是突变点，共现是两条并行接近的线，未知偏离是不在任何已知正常簇中的线。六种线对应六种读法，覆盖从已知风险到未知风险的完整谱系。

线形态 对应的风险语义 判据的核心 归到哪一级理解
平滑的线 正常穿行 位置随时间平滑变化，路径效率高 作为正常基线的一部分，不触发告警
水平段 异常逗留 位置不变、时间流逝，停留时长超出区域正常分布 识形态——已知苗头
折返线 反复徘徊 方向反转频繁，路径效率极低 识形态——已知苗头
突变点 倒地 / 占道 / 禁区进入 线上发生不可逆的形态跳变，如宽高比反转、位移趋零 识形态——事实判断
两条并行线 共现 / 结伴 两条线在时间轴和空间轴上持续接近 识形态——已知苗头
不属于任何已知模式的线 未知偏离 不在任何已知正常簇中，偏离程度高 辨偏离——未知候选
为什么用“线”而不是“动作”来定义分析对象：动作是瞬时的、局部的，而风险苗头往往是时间维度上的模式——异常逗留需要看几分钟的停留，反复徘徊需要看几十秒的轨迹形态，共现需要看多天的累积。用“线”作为分析对象，才能把这些时间维度上的模式统一到同一个框架里。
本章讲清了系统在读什么——时空中的六种线。那么这些线怎么建出来、怎么读、怎么用？下一章回答“怎么建”——两条实施路径，路径 A 用公开数据快速跑通，路径 B 用真实数据从零搭建。 → 下一章：怎么建——两条实施路径

三、怎么建：两条实施路径路径 A 公开数据先行，路径 B 真实数据为骨架；区别不在架构，而在数据策略

两条路径，区别不在架构，而在数据策略。 路径 A用公开数据先把成熟平台跑通，真实数据只做少量校准——产出的是认知：通用阈值在你的场景哪里不准、需求方对“系统能看见什么”的直观理解。
路径 B用真实自采数据做骨架，从零搭建三层处理和记忆基座——产出的是架构：可控、可解释、能按需求演进。
两条路径不互斥：路径 A 可以作为路径 B 的快速原型，先验证需求，再决定哪些模块值得自建。

路径 A：公开数据先行，1—2 个月跑通闭环

A公开数据
基于成熟平台快速搭建适合“先让需求方看到系统能跑”的阶段
六步

这条路径的核心是不自己训练大模型，用 videopipe-fastapi 等成熟平台的内置能力快速搭建，先用公开数据集验证平台能跑，再接真实视频做少量校准。产出的是认知，不是最终交付物。

1
部署平台基础环境
按官方 README 用 docker-compose 拉起 PostgreSQL、Milvus、Kafka、MinIO，pip install -r requirements.txt，启动 FastAPI 后端和 Vue3 前端。坑主要在 Kafka 的 advertised listeners 和 Milvus 的内存要求，不在代码本身。
需要哪类数据
无——这一步只验证环境能起来。
2
感知 / 理解用公开数据集验证预置行为检测
把 MOT17 或 Loitering Dataset 转成平台支持的输入格式，启用长时间徘徊、人群聚集、摔倒三个预置检测，跑通“检测→规则→报警”链路。目的不是验收，是确认平台能正常工作。
需要哪类数据
MOT17 验证跟踪与轨迹分析 Loitering Dataset 验证徘徊检测 PAB 验证倒地/躺卧姿态
数据细节见第四章 B 类 · 参考公开数据集
3
感知接 1—2 路真实视频，观察通用阈值偏差
用真实公共空间视频接入平台，跑 1—2 天，记录误报和漏报的具体模式：摊位区正常交易被误判为徘徊、货架后消失被误判为异常逗留、出入口高峰聚集被误报等。这一步产出的是“通用阈值哪里不准”的清单。
需要哪类数据
真实视频 1—2 路，1—2 天，仅用于观察，不做训练
数据细节见第四章 A 类 · 采集方式
4
理解用少量真实正常数据校准区域分层阈值
采集每个区域 2—3 天的正常数据，统计每个区域的停留时长分布、人数分布，把平台的预置阈值改成区域分层阈值。这一步能消除大部分“正常交易被误报为徘徊”的问题。
需要哪类数据
真实正常数据（A类） 每区域 2—3 天，量小但必须有，同时写入记忆基座
数据细节见第四章 A 类 · 规模与采集时机
5
理解从真实数据中人工筛困难负样本
平台不会自动标出“蹲取、搬运、正常聚集、等人”这些片段，需要人工过一遍，形成误报压测集。这是路径 A 唯一需要额外人工投入的环节，但不做，上线后会被误报淹掉。
需要哪类数据
真实数据（C类） 从步骤 3—4 的数据中定向筛选，每类 ≥200 段
数据细节见第四章 C 类 · 采集方式与规模
6
理解（可选）补偏离评分与语义归因
平台本身没有“分层基线偏离”层。可以在报警链路之后挂一个轻量偏离评分模块，把“规则未命中但轨迹形态不寻常”的片段也捞出来；平台的 Qwen-VL 二次确认可以复用，但只做解释，不替规则做判决。
需要哪类数据
真实正常数据 复用步骤 4
数据细节见第四章 A 类
路径 A 的数据底线：公开数据可以让你把平台跑起来、验证功能是否正常，但阈值校准和困难负样本必须用真实数据。路径 A 可以不用真实数据做训练，但不能不用真实数据做校准。

路径 B：真实数据为骨架，4—6 个月从零搭建

B真实数据
按三层处理逐层落地适合“架构可控、能按需求演进”的阶段
七步

这条路径的核心是自己搭“时空记忆智能体”，按感知→理解→决策三步逐层落地，记忆基座与感知同步建设。真实自采数据是骨架，公开数据只用于检测/跟踪骨干的预训练和方法论参照。产出的是最终交付架构。

1
感知检测 + 跟踪 + 质量门控
YOLO11n 用 COCO 预训练权重起步，在 CrowdHuman 上微调；跟踪用 BoxMOT + ByteTrack，在 MOT17 上验证基线；质量门控用轻量分类器输出亮度、模糊、遮挡比例。感知的产出同时向下写入记忆基座。
需要哪类数据
CrowdHuman 检测骨干微调 MOT17 / DanceTrack 跟踪基线验证 真实退化数据（D类） 夜间/沙尘/逆光 ≥80 小时，质量门控训练
数据细节见第四章 A 类、D 类
2
记忆基座轨迹库 + 向量索引（与感知同步建设）
注意：这不是主链上的一个顺序步骤，而是与感知同步建设的支撑设施。每条轨迹结束后，外观向量写 Milvus，结构化字段写 PostgreSQL（trace_id、camera_id、起止时间、区域序列、标签、质量分、关联置信度），媒体片段写 MinIO。四类索引：时间、空间、向量、ID。
需要哪类数据
真实正常轨迹（A类） 连续采集 3—4 周（150—200 小时），记忆基座的第一批数据，辨偏离的唯一输入
数据细节见第四章 A 类 · 规模与采集时机
3
理解①识形态：规则引擎
纯 Python 实现，阈值可配置化。核心规则：异常逗留（停留 > 区域 95 分位 + 路径效率 < 0.4）、反复徘徊（反转 ≥ 3 次 + 效率 < 0.3）、快速聚集（60 秒内人数从 <3 到 ≥6）、倒地（宽高比反转 + 位移 ≈ 0 + 持续 ≥ 30 秒 + 不在正常蹲取区）。
需要哪类数据
真实正常数据（A类） 建立区域分层阈值分布 真实正例（B类） 几十条即可校准检出率 Loitering Dataset 徘徊参数化方法参考 PAB 倒地姿态辅助参考
数据细节见第四章 A 类、B 类 · 逐类详细规划
4
理解②辨偏离：分层正常基线
这是路径 B 的核心增量，也是平台没有的。只学正常样本，按区域、时段、人群类型建分层基线（孤立森林或轻量 Bi-LSTM-AE），输入是滑动窗口内的轨迹特征向量。产出不是语义标签，而是“非典型轨迹”候选 + 偏离分数，候选进巡检池，不进实时告警。
需要哪类数据
真实正常数据（A类） 这是唯一输入，公开数据完全无法替代，从记忆基座读取
数据细节见第四章 A 类 · 规模与关键约束
5
理解③释归因：VLM 零样本翻译
对偏离候选的轨迹片段生成自然语言描述，零样本语义评分，把“统计偏离”翻译成“人能理解的描述”。参考 AnyAnomaly 的零样本 VQA 思路，不训练、不微调。边缘算力紧张时，候选片段回传服务器异步归因。
需要哪类数据
真实偏离候选 用于人工评估描述质量 AnyAnomaly 方法参考，无需训练数据
数据细节见第四章 B 类 · 可参考的公开数据集
6
决策分发 + 回溯 + 主动检索
FastAPI 暴露接口；Kafka/Redis 做报警过滤去重；SigLIP 做主动查询（图像或文本找特定的人），低分候选进人工确认队列；Vue3 或轻量前端做俯视地图、事件时间轴、轨迹回放。回溯时查询记忆基座，按时间、空间、外观找到历史线。
需要哪类数据
真实回溯测试集（E类） 每类事件 ≥20 段，用于验收和演示 RSTPReid SigLIP 检索阈值校准
数据细节见第四章 E 类、参考公共数据集总表
7
部署边缘落地：8 路 1080p
单节点 AGX Orin 64GB 余量充足；或 2×Orin NX 16GB 拆分，每节点 4 路，跨节点轨迹元数据聚合。DeepStream 提供 NVDEC 硬解、TensorRT 推理、NvDCF 跟踪的零拷贝流水线。DeepStream 只负责把延迟和功耗压下来，规则、基线、归因仍在你的上层模块。
需要哪类数据
真实运行数据 现场连续运行，收集误报/漏报，回传困难样本持续迭代
数据细节见第四章 A 类、C 类 · 持续迭代部分
路径 B 的数据底线：公开数据只能做两件事——检测/跟踪骨干的预训练和方法论参照。记忆基座的分层基线、困难负样本、回溯测试集，公开数据一律不能替代，因为它们是“你场景的正常”和“你场景的异常”。数据采集不是前置阶段，而是从感知层开始贯穿始终的并行线。

两条路径怎么衔接

路径 A 产出的三样东西 ① “通用阈值在你的场景哪里不准”的清单
② 从真实数据中筛出的困难负样本集
③ 需求方对“系统能看见什么”的直观认知
→
路径 B 直接复用这三样东西 ① 清单决定哪些规则需要重点校准
② 负样本集直接进入误报压测
③ 直观认知决定一期范围优先覆盖哪几类
建议的推进节奏：先用 路径 A 跑 1—2 个月，用公开数据把平台跑通，接 1—2 路真实视频暴露阈值偏差，同时和需求方对齐“一期覆盖哪几类可定义风险”和“能否组织现场演练”。路径 A 跑通后，再决定路径 B 的投入范围。

技术选型对照表

路径 B 每一层用到的具体技术选型如下。第一版优先用轻量、可替换的开源件，不追求最前沿；等闭环跑通、数据到位后，再逐层升级。

层 组件 选型 选型理由 / 备选
感知 检测器 YOLO11n（Ultralytics） 轻量、CPU 可跑、社区成熟；备选 RT-DETR（精度更高但边缘端吞吐差）
感知 跟踪器 BoxMOT + ByteTrack ByteTrack 保留低分框的两阶段关联，适合遮挡恢复；BoT-SORT 作为精度对照备选
感知 质量门控 MobileNetV3 级轻量分类器 输出亮度、模糊、遮挡比例、逆光标记，作为下游置信度折扣因子
记忆 向量存储 Milvus 向量检索事实标准；备选 FAISS（更轻但无分布式）
记忆 结构化存储 PostgreSQL 轨迹元数据、区域序列、标签、质量分

理解① 规则引擎 纯 Python 自建 阈值可配置化，按区域和时段分层；不依赖外部规则引擎
理解② 正常基线 孤立森林 / 轻量 Bi-LSTM-AE 只学正常样本，输出偏离分数；不追求深度模型，先跑通再升级
理解③ 语义归因 Vision-LLM 零样本（参考 AnyAnomaly） 不训练、不微调；边缘算力紧张时服务器端异步归因
决策 服务框架 FastAPI 暴露轨迹查询、事件分发、回溯检索接口
决策 消息分发 Kafka / Redis Stream 报警过滤、去重、防抖
决策 主动检索 SigLIP（DeepStream 插件或 ONNX 服务器） 图像或文本找特定的人；低分候选进人工确认队列
决策 展示 Vue3 或轻量 Web 前端 俯视地图 + 事件时间轴 + 轨迹回放 + 质量面板
部署 边缘运行时 DeepStream + TensorRT NVDEC 硬解、零拷贝流水线；只负责把延迟和功耗压下来
部署 边缘硬件 AGX Orin 64GB 或 2×Orin NX 16GB 8 路 1080p；单节点或双节点拆分，视成本和冗余需求

A
正常基线数据 量最大，最早启动，持续最久
辨偏离的唯一输入
采集方式
8 路摄像头连续采集，覆盖完整作息周期（早市、午间、晚市、夜间），不抽样。
规模
连续 3—4 周，每路每天至少 4 个时段，累计约 150—200 小时。
标注强度
轻标注：只标区域多边形、时段划分，不需要逐条轨迹打标签；轨迹由算法自动生成，人工抽检 10% 校验。
采集时机
项目启动后第一批启动，持续到理解层建成。它是“辨偏离”唯一输入，也是记忆基座的第一批数据。
责任方
项目方主导采集；需求方提供场地、时段权限和存储空间。
关键约束
必须连续而非抽样——夜间游荡、清晨聚集、周末人流变化，只有连续覆盖才能形成可信的基线分布。
可参考的公开数据集 · 仅用于验证流程和算法骨架
MOT17 / MOT20：行人多目标跟踪基准，用于验证你的检测+跟踪流水线能否稳定输出轨迹。MOT17 训练集 14 个序列、15948 帧、1638 个身份，场景相对规整，适合建立跟踪基线。
CrowdHuman：约 15 万张密集人群图像，用于检测器的遮挡鲁棒性预训练。它不能替代你的正常基线，但能让检测器在“人被货架挡住一半”时召回更稳。
DanceTrack：外观相似、频繁遮挡、非线性运动，与“购物/穿行/折返交替”的关联困难高度同构。用它测试跟踪器，可以预判你的轨迹在真实场景中的断裂风险。
边界：公开数据集的“正常”不是你的“正常”。它们只用于验证感知层能跑、跟踪器选型合理，不能写入记忆基座。
B
正例 / 苗头样本 稀缺，靠三条路补
规则阈值校准
采集方式
三条路并行：历史录像回溯（从处置记录/报警记录反查对应时间段录像）、受控现场演练（非营业时段模拟倒地、逗留、折返、聚集）、公开数据集补位（只补方法论，不补场景）。
规模
每类目标 几十条即可——规则阈值只需要少量正例校准，不需要几千条训练。不追求统计显著的召回率评估。
标注强度
强标注：逐段标注事件类型、起止时间、涉及轨迹、触发所依据的轨迹字段（如“停留 8min + 路径效率 0.21 + 主通道”）。
采集时机
项目启动后尽早启动，因为历史录像调取和现场演练组织都需要需求方协调，周期长。如果需求方不愿意组织演练，正例只能靠历史回溯和公开数据，验收口径要相应放宽。
责任方
需求方提供历史录像和演练组织；项目方负责筛选和标注。
关键约束
正例稀缺不会让项目做不了——规则和基线都不靠正例训练，正例只用于调阈值和定性验证。但必须提前和需求方对齐“演练能否组织”。
可参考的公开数据集 · 方法论参照与演练环境
Loitering Dataset（WACV 2024）：与“徘徊”最直接相关的公开标注数据集。将徘徊判据参数化为移动方向性、步速、停留时间，覆盖晴、雨、雪、雾多种条件，标注 31 天、约 1.97 万个 ID，其中 80.44% 为非徘徊。代码和标注在 github.com/johnnynunez/RS-WACV24_Loitering。演练用法：用它的轨迹标注验证你的“路径效率+方向反转”规则能否区分徘徊/非徘徊，作为阈值校准起点。
CASIA 行为分析数据库：中文行为数据集，明确包含“徘徊”类别（“一人来来回绕车走几次”）。分辨率较低（320×240），需签协议申请，但提供了可见光域下的徘徊样本，可以直观观察徘徊在画面中的视觉表现。
ShanghaiTech / UCF-Crime：视频异常检测经典 benchmark，用于验证“正常建模 + 异常评分”这条技术路线是否跑得通。它们的异常类别较粗（暴力、破坏、事故），不能直接迁移到你的细粒度行为，但可以证明方法可行。
PAB（ICCV 2025）：百万级合成异常行为图像 + 1978 张真实测试图，覆盖躺卧、摔倒等关键姿态。可用于“蹲 vs 倒”的困难区分参考，但合成图像的域与真实公共空间差异大，只能作为辅助训练信号。
YOLO 异常行为数据集：包含 9100 张 YOLO 格式标注图像，定义了 5 类行为（non_pedestrian、reverse、sit、sleep、stand）。其中的 sit 和 sleep 类别，可以为你区分“正常蹲坐”与“异常倒地/躺卧”提供标注视角的参考。
C
困难负样本 决定系统上线后能不能用
误报压测
采集方式
从 A 类正常数据中定向筛选——不需要额外采集，但需要人工过一遍。典型片段：蹲下取物、弯腰搬运、推车临时停放、正常交易聚集、出入口等人、摊位前长时间议价、货物临时堆放。
规模
每类 ≥200 段，每段 15 秒—3 分钟。
标注强度
中等标注：标注片段起止时间、所属类别、区域。
采集时机
A 类数据积累到 2 周左右即可开始筛选，必须在试运行前完成压测——不专门采集，系统上线第一天就会被误报淹掉。
责任方
项目方主导筛选和标注；需求方可以参与确认“哪些是正常行为”。
关键约束
这是 A 类标注之外唯一需要额外人工投入的环节，但也是决定系统可用性的关键。
可参考的公开数据集 · 边界定义与负样本思路
Loitering Dataset：它明确区分了徘徊与非徘徊（80.44% 为非徘徊），这为你定义“正常交易停留”与“异常徘徊”的边界提供了负样本比例和参数化思路的参考。
YOLO 异常行为数据集：其中的 sit、stand 类别可以作为“蹲坐/站立”正常姿态的参照，帮助你校准“正常蹲取”与“异常倒地”的边界。
边界：公开数据集没有你场景的“摊位区正常交易”“货架后正常取货”这类负样本，困难负样本必须从你的真实数据中筛，公开数据只能参考标注视角。
D
退化条件数据 低照度、遮挡、逆光、沙尘
质量门控
采集方式
从 A 类中筛选 + 针对性补采：夜间低照度、沙尘天气、出入口逆光、雨雪后地面反光、货架/推车重度遮挡。沙尘天气不可控，需提前部署持续录制，事后筛选。
规模
≥80 小时，其中夜间至少占一半。
标注强度
弱标注：只需标注退化类型和严重程度，不需要轨迹标注。
采集时机
与 A 类同步启动，感知层训练前必须到位——质量门控的轻量分类器需要它来训练“这帧可不可信”。
责任方
项目方主导；需求方提供沙尘天气的持续录制条件。
关键约束
夜间、沙尘、逆光是必须面对的真实条件，不能假设所有帧都“干净”。质量门控不是可选项。
可参考的公开数据集 · 退化条件与域适应参考
Loitering Dataset：覆盖晴、雨、雪、雾多种环境条件，虽然它是热成像域，但其退化条件下的轨迹标注方法论可以借鉴——如何在低质量条件下仍然保持轨迹语义的可比性。
LLVIP：低照度可见光-红外配准数据集，可用于训练质量评估/退化分类器，让系统知道“这帧质量下降了，证据可信度要打折”。你的摄像头是可见光，重点不是红外融合，而是退化识别。
边界：退化条件的核心是标记哪些帧不可信，而不是“修复”图像。生成式增强带来的伪影可能比退化本身更危险。
E
回溯测试集 验收依据，最后成型
验收与演示
采集方式
从历史录像和现场演练片段中挑选，包含真实事件或可控模拟事件。
规模
每类事件 ≥20 段。这个数量只够做定性验证和演示，不够做统计显著的定量评估——这一点要提前和需求方说明。
标注强度
强标注：逐段标注事件类型、起止时间、涉及轨迹、触发依据。
采集时机
最后成型，但历史录像的调取要尽早启动——它和 B 类正例共用同一批历史素材。
责任方
双方共同确认：需求方提供历史素材和演练记录，项目方整理和标注。
关键约束
这是唯一能验证“系统在真实场景中能不能用”的数据，不能用公开数据集替代。
可参考的公开数据集 · 仅用于对比实验和方法验证
ShanghaiTech / UCF-Crime：可以作为“你的系统”与“公开 VAD 方法”的对比实验，证明你的路线在公开数据上可行，但不作为你的验收依据。
Loitering Dataset：可以作为徘徊检测的对照 benchmark，报告你的方法在该数据集上的表现，但你的验收仍然以自建 E 类回溯测试集为准。
边界：E 类回溯测试集必须来自你的真实场景或演练，公开数据集只能用于“证明方法可行”，不能用于“证明系统在你的场景可用”。

五、往哪走：三步演进路线视频单模态 → 多模态物理传感 → 多源社会数据融合

范围声明：本章描述的是演进方向，不是本期交付承诺。 本期交付范围是第一步视频单模态。第二步和第三步是后续规划，它们的启动时机、投入规模、合规审批都需要在第一步跑通后另行决策。列出它们的目的不是承诺功能，而是说明技术路线的完整性——确保第一步的架构设计不会把后续演进的路堵死。
第一步当前
视频单模态把“建线 → 读线 → 用线”跑通
本期交付

用第三章的路径 A 或路径 B，以摄像头视频为唯一输入，完成感知建线、理解读线、决策用线，记忆基座存住轨迹。这是所有后续演进的地基——如果第一步的轨迹不稳、语义不准，加再多传感器和数据都没有意义。

感知视频检测 + 单镜跟踪 + 跨镜关联；验收：稳
理解识形态 + 辨偏离 + 释归因；验收：准
决策处置告警 + 关注线索 + 共现图；验收：快
记忆基座：轨迹库——存带 ID 的时空曲线、外观向量、区域序列、标签、质量分。四类索引：时间、空间、向量、ID。
第二步后续
多模态物理传感用物理传感器补摄像头的盲区
后续规划 · 不承诺

引入红外热成像、音频、毫米波雷达三类传感器，解决摄像头结构性缺失的问题。这一步的核心不是“多装几个设备”，而是为感知层补上摄像头看不见的那几条线，并让理解层获得摄像头无法提供的物理证据。

传感器 解决什么问题 在系统中的落点 边界
红外热成像 完全黑暗、强逆光、轻雾条件下仍能输出人体轮廓；不记录面部纹理，隐私友好 补感知层的夜间和逆光轨迹；为“倒地”提供姿态持续性和体温分布的物理证据 空间分辨率低于可见光，不适合精细外观检索；对环境热源敏感，需校准
音频（麦克风阵列） 360°覆盖，在视觉确认之前捕获呼救、尖叫、玻璃破碎、剧烈撞击、人群骚动 作为触发级调度的前置信号——异常声音触发关注，摄像头转向或调取对应区域 嘈杂公共空间中误报率上升；持续采集有隐私负担，需严格限定“监听什么”
毫米波雷达 穿透非金属障碍物，在完全黑暗和视线被完全遮挡时仍能探测人体存在、距离、速度和朝向 补感知层遮挡和非视距下的“是否存在”；为“盲区停留”提供决定性证据 空间分辨率远不及摄像头，无法做外观检索；点云语义解释依赖模型，标定迁移成本不低
超声传感器 近距离存在检测 不建议纳入——易被衣物吸收、多径散射严重、更新率低 更适合狭窄通道存在检测，不适合作为感知层主传感器
感知夜间/逆光/遮挡下轨迹不丢；轨迹增加“证据来源”维度
理解“倒地”从单帧姿态升级为“姿态持续性 + 无主动恢复 + 无呼救声”的多证据事件
决策音频触发关注、摄像头转向确认、雷达核实盲区——从“看到才报”到“先听后看”
记忆基座扩展：从“轨迹库”扩展为“多模态时空证据库”——在某个时空位置，有哪些传感器观测到了什么，各自置信度多少。轨迹的“线”可以由可见光框连成，也可以由热斑或雷达点云连成；理解层读取的是这些证据的并集，而不是某一种模态的序列。
边界与建议：热成像分辨率低，不做外观检索；音频在嘈杂环境误报率上升，且持续采集有隐私负担；雷达点云语义解释依赖模型，标定迁移成本不低。建议以“感知层补盲”为第二步首要目标，理解层的多证据融合作为第二步后期目标，决策层的协同调度作为远期方向。
第三步远期
多源社会数据融合从“个体观察者”升级为“关系解读者”
远期方向 · 合规前置

引入社交网络、通信记录、业务与行政数据，把视频的“共现网络”升级为“社会关系网络”。核心跨越在于为匿名轨迹 ID 注入“关系”与“身份”的语义——从“谁和谁经常一起出现”走向“谁和谁是什么关系、这个群体是否在协同行动”。

欧盟两个项目为这条路径提供了参照：MOSAIC 证明在视频之外引入文本和结构化记录后，社交网络分析可以作为理解层的正式组件；PREVISION 展示了多源大数据流经语义整合构建动态知识图谱、并用于预测的完整链条。

数据维度 具体数据 在关系分析中的作用
身份关联 社交账号、设备特征码、实名信息、生物特征（合规前提下） 把匿名轨迹映射到真实实体，是连接线上行为与线下轨迹的桥梁

时空行为补充 交通出行、位置轨迹、消费行为 补充视频盲区的移动轨迹，反映生活轨迹和消费习惯
业务与行政 亲属关系、职业与组织关系、案件与事件关联 为关系提供官方背书，直接关联到具体事件和人员
多模态内容 文本内容、图像与音视频 通过自然语言处理和场景识别，辅助判断活动性质和关联人员
感知接入文本、通信记录等数据流，统一清洗、对齐、实体识别
理解新增社交网络分析模块——社区发现、关键节点识别、链路预测、协同行动识别
决策从“个体行为告警”扩展到“群体性风险预警”——识别潜在协同团伙、发现异常聚集的组织者
记忆基座扩展：从“多模态时空证据库”进一步扩展为“多模态实体关系库”——存储的不再只是轨迹，而是人、账号、设备、地点、事件、组织等实体及其相互关系，形成动态知识图谱的底层数据。
边界与前置约束：这一步涉及通信记录、社交关系等极高隐私敏感度的数据，合规复杂度非线性上升。必须建立数据分级授权、用途限定、匿名化与最小化、完整操作审计日志。建议在顶层设计阶段就把隐私合规框架与数据治理体系作为核心组成部分同步规划，而不是事后附加。
三步之间的关系：不是“第一步做完再做第二步”，而是第一步跑通后，第二步和第三步按需渐进。第二步的传感器扩展主要增强感知层的“稳”，对理解层和决策层是渐进增强；第三步的数据融合则会显著改变记忆基座的组织形态和理解层的能力边界。每一步都必须在合规框架内推进，尤其第三步——它的数据敏感度要求从设计阶段就把隐私保护作为核心约束，而不是事后补救。

演进对第一步架构设计的约束

虽然第二步和第三步不是本期交付，但第一步的架构设计不能把后续演进的路堵死。以下三条约束需要在第三章的实施中落实：

约束 具体要求 为什么
轨迹记录预留证据来源字段 每条轨迹记录增加“证据来源”字段（可见光/热成像/雷达/音频），当前只填“可见光” 第二步多模态扩展时不需要改表结构；记忆基座可以直接承接多模态证据
记忆基座预留实体关系扩展点 轨迹库的表结构预留“实体标识”和“关系类型”两个可空字段，当前不填充 第三步实体关系库扩展时可以在同一基座上演进，而不是另建一套存储
合规框架从设计阶段建立 第一步就明确数据分级、访问控制、操作审计日志的框架，即使当前只有视频数据 第三步引入高敏感数据时，框架已经存在，只需扩展授权范围；而不是从零建合规体系
这三条约束的成本很低——预留字段、建立框架，在第一步的实施中几乎不增加工作量。但它们的价值很高：让第一步的架构成为后续演进的起点，而不是需要推倒重来的终点。
本章讲清了往哪走——第一步视频单模态是本期交付，第二步多模态传感、第三步社会数据融合是后续方向。那么每一步做得好不好，怎么衡量？下一章讲验收口径——正例稀缺的情况下，不能按常规指标验收。 → 下一章：怎么验收——分层验收口径

六、怎么验收：分层验收口径正例稀缺，不能按常规指标验收

核心判断：不承诺“异常召回率 95%”，因为场景没有足够正例支撑这个承诺。 承诺的是——已知风险不漏、未知偏离能捞、捞出来能解释、误报量在运维可承受范围内，并且每一项都有可核验的测试集。验收按能力层分层设计，每层有不同的验收方式和可承诺指标。
能力层 验收方式 可承诺的指标 数据依赖
感知（稳） 正常数据上评估 跟踪 IDF1、遮挡后 ID 恢复率、轨迹完整率 不需要正例，A 类 + D 类即可
理解① 识形态（准） B 类正例 + C 类困难负样本 正例上报告检出率（非召回率）；困难负样本上报告误报率，按区域分层 B 类几十条 + C 类每类 ≥200 段
理解② 辨偏离（捞得到） E 类回溯测试集 已知事件落入偏离候选池的覆盖率；候选池日均条数（运维可承受性） A 类正常基线 + E 类回溯测试集
理解③ 释归因（说得清） 人工评估 需求方人员判断“描述是否有帮助”的有用率，不做自动化指标 真实偏离候选 + 人工评估
决策（快） 端到端运行 告警延迟、线索密度、回溯检索响应时间 真实运行数据 + E 类回溯测试集
记忆基座（全） 支撑性评估 轨迹完整率、检索命中率、跨时段关联正确率 A 类正常基线 + 真实运行数据
为什么这样验收：正例稀缺是场景的客观事实，不是技术能力不足。感知层不需要正例，可以正常评估；识形态的规则阈值只需要几十条正例校准，报告检出率而非召回率是诚实的；辨偏离本质上不依赖正例，它只学正常样本，用回溯测试集评估覆盖率是合理的；释归因是解释器不是判决器，人工评估有用率比自动化指标更贴近实际价值。
本章讲清了怎么验收——分层验收，每层有不同的可承诺指标。最后，还有十项需要需求方在项目启动阶段明确表态的事项。这些事项直接决定数据采集能否推进、验收口径怎么定。 → 下一章：需要需求方拍板的事项

这份文档回答了六个问题：是什么、读什么、怎么建、用什么建、往哪走、怎么验收。
是什么——三层处理 + 一个基座：感知建线，理解读线，决策用线；记忆库存线，横贯底部。
读什么——时空中的六种线：正常穿行、异常逗留、反复徘徊、倒地、共现、未知偏离。
怎么建——两条路径：路径 A 公开数据先行快速出效果，路径 B 真实数据为骨架从零搭建。
用什么建——五类数据：正常基线、正例、困难负样本、退化条件、回溯测试集。公开数据集只做参照，真实数据是骨架。
往哪走——三步演进：视频单模态 → 多模态物理传感 → 多源社会数据融合。第一步是本期交付，后两步是后续方向。
怎么验收——分层验收：感知看稳、识形态看检出率、辨偏离看覆盖率、释归因看有用率。
先跑通，再搭稳；公开数据验证需求，真实数据交付架构。 —— 三层处理，一个基座；三步演进，分层验收。
